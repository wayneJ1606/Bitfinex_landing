# P0 Bitfinex 放貸策略最佳化設計

狀態：已由使用者確認

確認日期：2026-08-19

優先級：P0（業師建議版／結案報告主線）

## 1. 文件定位

本文件是 P0 放貸策略最佳化的正式需求與驗收依據。它承接現有的下一時間點利率預測模型，再加入成交機率、等待時間、資金閒置、拆單、複利及市場容量模擬。

若舊文件仍出現「160 USDT 與 10,000 USDT 兩組本金」或「累積 7 天即可正式回測」，以本文件的新定義為準。`todo.md` 負責追蹤待辦狀態，`progress.md` 負責記錄已完成成果，本文件負責說明需求、設計及完成標準。

## 2. 產品目標

在相同 30 天評估期間內，針對每個本金級距找出期末「本金＋累積淨利息」最高的放貸組合。計算必須納入：

- 等待成交造成的資金閒置；
- 實際借出秒數；
- Bitfinex 放貸手續費；
- 本金與已到帳利息的再投入；
- 市場可成交容量；
- 未成交後重新調價的等待時間。

主要推薦依總收益排序；另提供收益稍低但結果較穩定的替代方案。最佳化策略即使未勝過簡單基準，只要比較公平、結果可重現且限制如實揭露，仍可視為有效研究結論。

## 3. 官方計息規則

P0 只模擬一般公開掛單，不納入隱藏掛單與 LEO 折扣。一般公開掛單的手續費固定為利息收入的 15%。

使用 Bitfinex API 的小數日利率時：

```text
毛利息 = 本金 × API 日利率 ×（實際借出秒數 ÷ 86,400）
手續費 = 毛利息 × 0.15
淨利息 = 毛利息 × 0.85
```

API `RATE` 採小數表示，例如 `1% = 0.01`、`0.025% = 0.00025`，不得再次除以 100。利息按秒計算；借款人在特定情況下於一小時內手動歸還時，仍可能按至少一小時計息。掛單期限不等於資金保證借滿該期限，借款人可能提前歸還。

官方依據：

- <https://support.bitfinex.com/hc/en-us/articles/360024039494-How-are-the-Funding-interest-earnings-and-fees-calculated-at-Bitfinex>
- <https://support.bitfinex.com/hc/en-us/articles/213919589-What-fees-does-Bitfinex-charge>
- <https://docs.bitfinex.com/reference/rest-auth-funding-trades-hist>

## 4. 策略搜尋範圍

### 4.1 資產

- USDT：P0 必做。
- 產品與報告一律顯示 `USDT`；程式內若使用 Bitfinex 的 `fUST` 市場代碼，必須明確映射為 USDT，不得誤標為 UST 幣種。
- BTC、ETH：資料達門檻才產生策略；不足時必須顯示 `insufficient_data`。
- BTC、ETH 回測起點依當時 BTC/USDT、ETH/USDT 價格換算本金，收益全程以原資產計算；報告產生時再顯示當下 USDT 約值及查價時間。

### 4.2 本金與拆單

- 本金級距：1,000、2,000、3,000，依此類推至 10,000 USDT。
- 起始本金以每份 1,000 USDT 為原則拆分，最多同時十筆。
- 每筆可使用不同利率、期限與重新調價等待時間。
- 已到帳利息與歸還本金可在下一次配置時重新投入。

### 4.3 候選條件

- 放貸期限：2、5、10、30 天。
- 未成交後重新評估時間：1、3、6、12、24 小時。
- 候選利率：依當時以前的歷史利率分布，使用第 10、25、50、75、90 百分位作為五個代表性候選值；輸出必須列出實際測試值。
- 同一時間的模擬成交總額不得超過歷史市場可用量。

## 5. 資料與驗證方法

- 公開市場歷史資料是成交機率及等待時間的主要估計來源。
- 私人帳戶掛單與成交資料只用於校正及驗證；私人樣本不足不阻擋 P0 交付，但必須標示尚待驗證。
- 採 walk-forward 回測；每次決策只能使用該時間點以前的資料。
- 正式回測至少以最前 30 天作為初始歷史窗，再逐步向前評估；只計入後續結果已完整可觀察的決策點。
- 原有下一時間點利率預測模型作為策略輸入之一。
- 必須比較「有使用利率預測」與「未使用利率預測」的結果。
- 必須比較三種簡單基準：固定歷史中位日利率、FRR 市場利率、偏低利率快速成交。

### 5.1 正式結果資料門檻

- 至少連續 60 天 USDT 公開市場資料；
- 每小時資料完整率至少 90%；
- 不得出現超過 6 小時的連續缺漏；
- 每個被比較的「利率分位點 × 期限 × 等待時間」策略組合至少有 30 次可驗證機會。

未達門檻時仍可開發、試跑及產生介面，但所有輸出只能標示為「實驗結果／資料不足」，不得當作正式結論。

## 6. 系統設計

採「每日離線批次計算＋固定輸出檔＋本機唯讀介面」：

1. 現有公開與私人收集器持續保存原始資料。
2. 資料品質檢查先判定完整率、缺口、樣本數與資料新鮮度。
3. 成交統計層估計各利率、期限及等待條件的成交機率、等待時間與可部署金額。
4. 策略模擬層進行拆單、容量限制、手續費、閒置及複利計算。
5. Walk-forward 評估層與三種基準、有／無預測模型進行公平比較。
6. 每天台灣時間 10:00 產生 Markdown、CSV 及介面所需的唯讀結果。

這種方式讓三種輸出共用同一份計算結果，避免介面、CSV 與報告各自重算後產生差異。

## 7. 最終輸出

每個 1,000～10,000 USDT 本金級距至少顯示：

- 建議拆單筆數及每筆金額；
- 每筆建議日利率、期限與重新調價等待時間；
- 預估成交機率及等待時間；
- 毛利息、15% 手續費、淨利息與期末總資產；
- 資金閒置比例；
- 與三種基準策略的收益差異；
- 有／無利率預測模型的差異；
- 資料量、可信度與限制警告；
- 最高收益方案及較穩定替代方案。

最高收益方案依 30 天期末總資產排序；較穩定替代方案則在樣本達門檻的候選策略中，以 30 天淨收益第 10 百分位最高者選出，避免用主觀方式挑選看似穩定的結果。

交付形式：

- 白話版 `report.md`；
- 完整結果 CSV；
- 本機唯讀互動介面。

互動介面只允許選擇 1,000～10,000 USDT 本金、2／5／10／30 天期限及 1／3／6／12／24 小時等待條件；利率由已驗證的歷史分位點產生，不接受任意未回測值。主要呈現 30 天收益，年化報酬只能標示為換算參考值。

## 8. 錯誤處理與安全

- 當日資料不完整、收集失敗或模型計算錯誤時，不覆蓋上一次成功結果。
- 介面顯示更新失敗、資料過期、最後成功時間及錯誤原因。
- 私人原始資料只留在本機，不得推送 GitHub。
- 報告與介面只顯示彙總資料，不得顯示 API Key、帳戶識別資訊或完整掛單 ID。
- GitHub 只能保存無法識別個人帳戶的匿名統計成果。
- 系統不得包含送單、改單或取消真實掛單的能力。

## 9. P0 排除範圍

- 不預測 BTC、ETH 或 USDT 未來幣價漲跌；
- 不建議買入、賣出或換幣；
- 不自動執行任何 Bitfinex 帳戶操作；
- 不承諾固定收益或保證獲利。

上述項目待 P0 穩定後另立需求，不得在本階段自行擴大。

## 10. 完成與驗收標準

以下條件全部通過，P0 功能才算完成：

- 官方利息與 15% 手續費公式有自動測試；
- 十組本金級距均能產生結果；
- 所有期限及等待策略均有比較；
- 拆單、複利、成交量限制與閒置計算正確；
- Walk-forward 不使用未來資料；
- 三種基準及有／無預測模型均公平比較；
- Markdown、CSV 與互動介面的數字一致；
- 資料不足、更新失敗及過期狀態正確；
- 程式不具備任何真實掛單寫入能力；
- 相同資料與設定可在相同環境重現相同結果。

「功能完成」與「正式資料成熟」分開判定：程式可以先完成；未達第 5.1 節資料門檻時，結果仍只能是實驗版。
