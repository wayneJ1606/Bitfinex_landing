# Bitfinex 系統架構與資料流動態章節設計

## 目的

製作一段可獨立播放、也能嵌入結案報告的 HyperFrames motion graphic，以視覺化方式解釋 Bitfinex 放貸市場決策輔助系統的完整資料流。動畫只呈現已實作或已驗證的第一階段能力，不宣稱尚未產生的模型成效。

## 輸出規格

- 畫面比例：16:9
- 解析度：1920×1080
- 目標長度：約 25 秒
- 語言：繁體中文
- 聲音：無旁白；第一版不依賴音效也能完整理解
- 用途：結案簡報章節、獨立 MP4 片段
- 工作流：HyperFrames `motion-graphics`
- 專案目錄：`videos/bitfinex-system-flow/`

## 核心訊息

系統將 Bitfinex 即時 funding-book 資料，透過排程收集、可靠儲存、特徵工程與資料門檻檢查，轉換成可重現的模型評估輸出；資料不足時明確停止在 `insufficient_data`，不產生誤導性結果。

## 敘事節拍

### 0–3 秒：資料來源啟動

- 標題「Bitfinex 放貸市場決策輔助系統」快速建立。
- `fUSD`、`fBTC`、`fETH` 三個市場節點依序亮起。
- Funding-book rows 化為青藍色資料粒子。

### 3–7 秒：自動收集

- 資料粒子流向 GitHub Actions 排程節點。
- 顯示「每小時第 17 分」。
- 排程節點產生規律脈衝，傳達持續自動收集。

### 7–11 秒：可靠儲存

- 資料分流到 Raw CSV 與 SQLite。
- CSV 以日期與市場分層堆疊。
- 短暫顯示「UTC、去重、原子寫入」三個可靠性標籤。

### 11–15 秒：特徵工程

- 原始資料列收束成 snapshot 卡片，再轉換為特徵矩陣。
- 顯示代表性欄位：`weighted_avg_rate`、`rate_spread`、`rate_change`、`target_next`。
- 使用格線與矩陣填充效果強調結構化轉換。

### 15–19 秒：模型門檻

- 畫面中心建立「168 筆有效資料」進度環。
- 以目前真實狀態顯示每市場 80／168。
- 狀態標籤顯示 `insufficient_data`。
- 動畫明確表達「等待資料累積」，而不是模型失敗。

### 19–23 秒：模型與評估輸出

- 門檻後方預示三條模型路徑：`baseline_mean`、`baseline_previous`、`linear_regression`。
- MAE、RMSE、R² 卡片保持待啟用狀態。
- 四份固定輸出檔以線框卡片排列：features、status、evaluations、predictions。

### 23–25 秒：結論鎖定

- 全部節點縮合成完整資料管線。
- 結尾文字：「資料驅動、可重現、不自動下單」。
- 保留乾淨的 1 秒終止畫面，方便嵌入簡報。

## 視覺設計

- 背景：近黑藍色，帶低對比網格與輕微景深。
- 主色：Bitfinex 綠搭配青藍色資料流。
- 輔色：橙色只用於門檻未達與限制提示。
- 文字：粗體無襯線中文標題；技術欄位使用等寬字。
- 物件：圓角節點、細線框卡片、資料粒子、進度環、矩陣格。
- 動態：節點啟動、路徑追蹤、資料匯聚、數字計數、矩陣填充與鏡頭推進。
- 避免：交易 K 線、獲利箭頭、保證收益符號與真實下單介面。

## 資料真實性

- 使用目前已驗證的每市場 80 筆有效資料。
- 門檻固定為 168 筆。
- 不顯示尚未產生的 MAE、RMSE、R² 數值。
- 模型卡片標示為門檻達成後啟用。
- 清楚保留研究用途、不自動下單與不保證收益的限制。

## 驗收方式

正式 render 前產生三個 proof snapshots：

1. 自動收集與資料分流。
2. 特徵矩陣與 80／168 門檻。
3. 完整管線與結尾限制文字。

驗收重點：

- 1920×1080 畫面沒有裁切或文字溢出。
- 任意時間 seek 都能得到一致畫面。
- 不依賴旁白也能理解資料方向。
- 真實狀態與文件一致。
- HyperFrames lint、check 與 snapshot 驗證通過。
- 使用者審閱 proof snapshots 後才執行正式 render。

## 範圍外

- 不製作完整 13 章結案簡報。
- 不加入決策樹、XGBoost 或回測成果。
- 不虛構模型分數、收益率或成交率。
- 不加入私人 API、帳戶畫面或自動下單情境。
